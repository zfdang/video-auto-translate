# “匹配译文时间轴”算法简介

本文对应当前已合并的实现（2026-10-22）。

核心思路是：**把同一语境的相邻句子组成 cluster（局部语境组），固定每组的开头和结尾，允许组内各句调整起止时间，共享配音时间。** 每组独立计算，避免调整一路累积，导致后面的语音偏离视频内容。

## 处理流程

1. **实测正常语速时长。** 用当前选择的音色合成每句译文，裁去首尾多余静音并保留少量余量，测量实际朗读时长。应用中的匹配流程使用实际音频，不依靠字数估算。
2. **划分局部语境。** 根据原文、译文和原始时间，让语言模型把相邻且内容连贯的句子分组。模型只决定分组，不改写文本、不生成时间戳。服务不可用或结果不合法时，自动采用本地规则。
3. **在组内分配时间。** 以第一句原始开始时间和最后一句原始结束时间为外边界，预留短暂停顿，再按每句实测时长分配剩余时间。中间各句可以前移或后移。
4. **准备并试听结果。** 在“匹配译文时间轴”中完成必要的保调变速，生成可试听的配音，展示各句调整前后的时间。确认后统一应用，可以撤销。
5. **后续复用。** 在译文、音色和时间没有变化的情况下，生成、试听和导出复用已确认的音频，不重新调整每句语速或起始位置。修改后若正常语速放不下，需要重新匹配。

## 怎样分组

| 规则 | 当前实现 |
| --- | --- |
| 明显停顿 | 不跨越原始间隔 ≥ 0.65 秒的边界 |
| 组的跨度 | 多句组最多 16 秒；单句超过 16 秒时仍保留该句 |
| 语义分组 | 优先把同一地点、活动或意思的 2–5 句放在一起；2–5 句是提示偏好，不是硬性校验上限 |
| 本地分组 | 按相邻顺序合并，最多 5 句，同时遵守停顿和跨度限制 |
| 收尾孤句 | 本地分组时，若上一组至少 3 句且边界允许，将其最后一句移入收尾孤句所在组 |

模型每批最多处理 30 句，批次之间也会形成分组边界。返回结果必须完整保留所有句子及原顺序，且满足停顿、跨度限制，否则整份方案回退到本地分组。本地规则只参考时间邻近关系，不能保证真正理解语境。

## 组内怎样安排

设组跨度为 `T`，各句正常朗读时长为 `d₁、d₂……`，组内短暂停顿合计为 `P`：

```text
可用朗读时间 = T − P
组内统一速度倍率 r = max(1, 所有正常朗读时长之和 / 可用朗读时间)
各句目标朗读时长 = 正常朗读时长 / r
```

句间停顿先取原始间隔，并限制在 40–120 毫秒；若停顿总和超过组跨度的 8%，再等比例缩短。因此最终停顿可能小于 40 毫秒。

算法先从组尾倒推各句最晚能从哪里开始，再从组首向后排。在确保前后不重叠、后面的句子仍放得下的前提下，尽量保留原来的句子开始位置。第一句开始和最后一句结束始终固定在组边界。

例如，一组占据视频的 0–5 秒，两句正常朗读分别需要 3 秒和 1 秒，中间留 0.1 秒停顿。即使原来第二句在 1.1 秒开始，也可以移到 3.1 秒开始，让第一句完整说完；组仍在 5 秒结束，无需加速。末尾剩余时间保留静音，**不会为了填满画面而把短句拖慢**。字幕结束时间可以晚于该句实际声音结束时间。

时间紧张时，同组各句共享一个加速预算，长句可以使用邻近短句的余量。若整组依然放不下，则统一加速；当前界面对超过约 1.6 倍的句子提示偏快，但不因超过速度阈值而拒绝生成整句音频。最后一句的字幕区间可能包含尾部静音，其实际渲染倍率也可能低于组内计算倍率。

## 边界与局限

- 原始时间戳始终保留，重复匹配从原始边界重新计算。组不能向前后其他组借时间；未传入视频总时长也不会让最后一组额外向后延伸。
- 相邻原始时间重叠不超过 30 毫秒时，会缩短前一句的可用结束时间，原始记录不变。超过容差、修正后不足约 100 毫秒、存在无效时间或超出视频范围，仍会拒绝自动匹配。
- 固定组边界能够限制漂移，但不能保证组内每句话都与画面中的动作精确同步。分组过大、语境判断错误或内容过密，仍可能造成局部错位或明显加速；单句组也没有邻句余量可借。
- 算法不删减译文、不改写原文或译文、不改变视频速度。合成或渲染本身失败时，仍会报错；速度提示不阻塞并不等于所有输入都一定成功。

## 样例验证与实现位置

使用 `Tests/Fme9C5ShSr2fuWQ8_Translated.mp4` 对应的 25 句样例，上次本机验收中，本地规则形成 7 个组，调整了 18 个组内开始位置，25 句均可试听，并完成整片配音和导出；峰值所需倍率由旧逐句固定方案的约 2.03 倍降至约 1.58 倍。这是该样例的结果，其他文本、音色和分组可能不同。
