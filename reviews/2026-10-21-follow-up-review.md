## 结论

这一轮修复确有成效：重复翻译 ID 和 TTS 写入错误的崩溃路径已移除，重叠配音不再推移已有片段，播放高亮与编辑选中项也已分离。现有 **14 个测试全部通过**，Release 构建成功。

但新 main 仍有主要链路阻断：**ASR 接口调用 `asyncio.to_thread` 却没有导入 `asyncio`，所有进入该调用的转录请求均返回 HTTP 500**。此外，源媒体保护仍可被符号链接父目录绕过；词内拆分仍造成文字、词映射和时间不一致。这三项应优先处理。

对上轮 33 项逐一复核：**10 项原始故障已修复，17 项部分修复，6 项仍存在**。“已修复”只表示上轮描述的具体路径已移除，不表示整个相关功能已完整验收。例如仅译文模式不再回填原文，但新增了静默漏句问题。下文另列 **9 项本轮重点发现（3 项 P1、6 项 P2）**；其中包含旧问题残留，不能与上轮 33 项简单相加。

新增工程序列化值得继续完善，但目前没有接入保存/打开界面、自动保存或未保存提示，且会把在线 API Key 明文写进文档。字幕编辑的数据安全、可恢复性和时间轴一致性仍未达到首轮报告建议的交付条件。

## 证据口径

- **动态**：直接调用基线代码，在临时文件、合成音频/视频或本地假翻译服务上验证。
- **注入**：仅替换外部依赖或启动副作用；具体替换点见[验证记录](2026-10-21-follow-up-evidence.md)。不等同于真实模型/系统语音/GUI 的端到端验收。
- **静态**：追踪代码路径和调用关系，未声称实际执行对应界面或并发场景。
- P1 表示主要能力阻断、数据损失或核心时间对齐错误；P2 表示特定输入/操作下的功能、隐私或验证问题。没有发现新的 P0。

## 本轮重点发现

### FU01 · P1 · 转录路由缺失 asyncio 导入，直接返回 500（新增）

位置：[asr_server.py:358](../scripts/asr_server.py#L358)，以及文件导入区 12–25 行。

把推理移到线程的改动使用 `await asyncio.to_thread(...)`，但模块没有导入 `asyncio`。因此请求完成上传后，在推理前抛出 NameError，再由异常处理变成 HTTP 500；模型是否存在不影响这个故障。进程内 ASGI 请求得到 `{"detail":"name 'asyncio' is not defined"}`，显式 mock 模式也无法绕过该调用。

建议补齐导入，并新增通过真实路由发起 multipart 请求的测试，覆盖成功、依赖缺失和推理失败。仅做 Python 语法检查或直接调用 `run_local_transcription` 都发现不了此错误。

### FU02 · P1 · 输出路径别名仍可覆盖源视频（R01 残留）

位置：[VideoComposer.swift:41–50](../Sources/VideoAutoTranslateCore/Exporter/VideoComposer.swift#L41-L50)。

标准化字符串路径比较挡住了完全相同的路径，临时输出后替换也解决了导出失败先删目标的问题。但 `standardizedFileURL` 不解析符号链接父目录。源文件为 `real/sample.mp4`，输出为 `alias/sample.mp4`，其中 `alias -> real`，比较通过；最终替换仍落到源文件本身。

动态使用临时生成的一秒视频确认：导出被接受，源文件字节发生变化。没有使用用户媒体。建议同时比较解析符号链接后的路径和已有文件身份，在最终替换前重新检查全部输入资源；补充父目录别名、输入音频别名及失败保留旧目标的回归。

### FU03 · P1 · 词内拆分仍使文字与时间分离（R06 残留）

位置：[SubtitleManager.swift:22–49](../Sources/VideoAutoTranslateCore/Manager/SubtitleManager.swift#L22-L49)、[63–69](../Sources/VideoAutoTranslateCore/Manager/SubtitleManager.swift#L63-L69)。

新实现考虑了原文中词的实际位置，并拒绝总长不足 160ms 的拆分，修复了先前的部分映射及零时长问题。但先按原始光标位置截断文字，之后遇到词内光标时把整个词放到左句，只移动时间，不移动文字断点。

`Hello world` 的两个词分别位于 1–2 秒、2.2–3 秒。index=2 得到左句 `He` 却持有完整 `Hello` token、结束于 2 秒；右句 `llo world` 只持有 `world`。index=10 得到 `Hello worl` / `d`，右句没有词时间，切点还被单独限幅到 2.92 秒。正向词边界 index=6 则正常。

建议由同一个拆分提案同时决定文字断点、词归属和时间；词内位置应吸附到明确词边界，或进入人工对齐。失效映射应提示重新对齐，不能仅把时间夹进允许范围。最低时长也应与 [PRD 的 100ms 约束](../docs/PRD.md#L85)统一，而不是在实现中另设 80ms。

### FU04 · P2 · 工程序列化明文包含在线 API Key（新增）

位置：[ProjectState.swift:4–9](../Sources/VideoAutoTranslateCore/Models/ProjectState.swift#L4-L9)、[64–74](../Sources/VideoAutoTranslateCore/Models/ProjectState.swift#L64-L74)，[LLMConfiguration.swift:52](../Sources/VideoAutoTranslateCore/Models/LLMConfiguration.swift#L52)，[AppState.swift:367–371](../Sources/VideoAutoTranslateApp/AppState.swift#L367-L371)。

工程文档直接编码完整 `LLMConfiguration`，其中包括 `onlineAPIKey`。使用假 sentinel key 的动态验证确认，生成的 JSON 能直接读到它。工程一旦被备份、分享或提交到仓库就会连带暴露凭据。

当前保存函数尚未接入界面，因此本结论是新增文档格式/API 的泄露风险，不是已经发生真实用户凭据泄露。建议文档只保存提供方、地址、模型等非秘密配置，凭据放 Keychain 并通过本地引用恢复；用假 key 验证工程内容中不包含凭据。

### FU05 · P2 · cancelAllTasks 没有持有实际任务（R03 残留）

位置：[AppState.swift:39–41](../Sources/VideoAutoTranslateApp/AppState.swift#L39-L41)、[135–142](../Sources/VideoAutoTranslateApp/AppState.swift#L135-L142)、[267–269](../Sources/VideoAutoTranslateApp/AppState.swift#L267-L269)。

三个 Task 属性只被声明、cancel 和赋 nil，没有接收界面实际启动的 Task。generation 校验改善了切换媒体后的主要结果写回，但 `cancelAllTasks()` 本身取消的是 nil。延迟翻译验证中调用取消后，旧翻译仍返回并写入，状态显示“翻译完成”。相同请求直接对实际 Task 调用 cancel 则能取消网络请求，说明问题在句柄接线。

另一个静态残留是配音循环在 await 前检查 generation，却在 await 后直接写 `project.progress`；中间切换媒体仍可能把旧进度写到新项目。建议统一由 AppState 创建并持有任务，取消时推进失效代际，在每次 await 后校验归属再写任何状态。测试应区分“底层支持取消”与“应用取消入口真的取消了任务”。

### FU06 · P2 · 手动清空译文仍被迟到响应覆盖（R07 残留）

位置：[SubtitleTranslator.swift:124–125](../Sources/VideoAutoTranslateCore/LLM/SubtitleTranslator.swift#L124-L125)。

当前保护能保留请求期间修改的非空原文/译文。但条件额外允许 `item.translatedText.isEmpty`，把用户主动清空已有译文也当成可覆盖状态。初始译文 `Initial`，请求期间手动清空，迟到响应后变成 `Generated from old source`，已动态确认。

建议用原文/译文 revision 校验，至少要求当前值与请求快照完全相同；“用户有意清空”和“从未翻译”必须能区分。补充清空、编辑后改回、撤销、重译交错的测试。

### FU07 · P2 · 持久化时间绕过新限幅，格式化仍可崩溃（R27 残留）

位置：[TimeTypes.swift:20–22](../Sources/VideoAutoTranslateCore/Models/TimeTypes.swift#L20-L22)、[31–33](../Sources/VideoAutoTranslateCore/Models/TimeTypes.swift#L31-L33)，同文件 `CodableCMTime`。

`CMTime.from(seconds:)` 已将输入限制在十天并修正毫秒取整。但工程反序列化的 `value/timescale` 不经过这个构造函数。解码 `{"value":9223372036854775807,"timescale":1}` 后调用 `srtFormat`，`secondsValue * 1000` 转 Int64 超界，隔离子进程以信号 5 退出。VTT 和显示格式也存在同类未限幅转换（静态）。

另有格式量化问题：0.0001–0.0002 秒的合法 CMTime 区间通过 `end > start` 检查，却导出为 `00:00:00,000 --> 00:00:00,000`。建议在解码/导入边界验证项目版本、时间范围、timescale 和区间，并在输出精度上再次检查；格式化本身也应防溢出，不能依赖调用者只使用某个构造器。

### FU08 · P2 · 仅译文导出静默漏掉未完成行（修复 R31 引入的新行为）

位置：[SRTExporter.swift:37–60](../Sources/VideoAutoTranslateCore/Exporter/SRTExporter.swift#L37-L60)，[VideoComposer.swift:169–173](../Sources/VideoAutoTranslateCore/Exporter/VideoComposer.swift#L169-L173)。

仅译文模式现在不会偷偷回填原文，这是正确方向。但空译文被直接 continue，没有逐句错误或导出前确认。两句输入、一句未翻译时，动态导出的 SRT 只剩一句，调用正常成功；视频字幕路径也会跳过空内容（静态）。无效时间区间也被静默跳过。

建议导出前汇总未翻译、失效时间和待对齐行，允许用户明确选择修复、取消或接受跳过；结果应包含实际导出/跳过数量，不能把漏句当作无条件成功。对量化后零时长也应使用同一校验入口。

### FU09 · P2 · 空权重仍被判定为模型就绪（R26 残留）

位置：[ModelStorageManager.swift:310–328](../Sources/VideoAutoTranslateCore/ASR/ModelStorageManager.swift#L310-L328)，[asr_server.py](../scripts/asr_server.py) 的 `find_model_path`。

空目录不再直接通过，但判断只检查配置和权重文件名；Swift 还允许任意总大小超过 50MB 的目录通过。临时目录中仅放 `{}` 配置与零字节 `model.safetensors`，Swift 状态为 ready，Python 查找也接受该目录。下载中断后仍可能显示“已就绪”，真实加载才报错。

建议使用模型类型对应的完整性清单、非零权重及索引分片检查，下载完成后原子发布 ready 标记；最终可加载性检测失败时回到可重试状态。不要把大小阈值作为独立的有效性证明。

## 字幕编辑和 UI 的下一步

本轮最需要避免的是“界面操作成功，但内部状态不一致”。建议把核心操作做成可校验、可撤销的编辑事务：拆分先展示文字与词边界候选、前后时间和译文分配，确认后一次性提交；调时显示邻句冲突、最小时长和配音实际时长；修改原文、译文、音色后清晰标记需要重新对齐/生成的内容。

保存工程应有可见入口、未保存状态和切换媒体前的处理流程，恢复时校验媒体及派生资源。导出前集中列出缺译、无效时间、待对齐和配音溢出，提供明确的修复或接受选项。当前“把整段译文放左句”“跳过空行”“时间限幅”都不能替代这些用户可理解的决策。

建议修复顺序：FU01 → FU02 → FU03；随后闭环保存恢复、任务取消与编辑版本；再处理凭据隔离、导出完整性和模型准备。验证应优先覆盖这些真实边界，而不是只增加正常输入的测试数量。
