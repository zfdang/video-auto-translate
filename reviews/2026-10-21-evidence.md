### 结果解释限制

- ASGI 请求在同进程直接进入应用中间件，能验证认证与 CORS 配置，但未验证浏览器的私有网络权限交互。
- 推理阻塞用 350ms 同步函数替代真实模型，证明事件循环的阻塞结构；不用于估计 Qwen 性能。
- TTS 在临时源文件副本中只替换 synthesizer，注入 PCM 与结束回调，保留被评审的 continuation 控制流；不用于估计系统语音服务的故障频率。
- 同路径导出使用无媒体价值的临时 sentinel。被删除的是测试文件，不是用户输入；生产函数的预删除行为发生在媒体读取前。
- 配音裁短和重叠测试使用原生音频引擎及合成信号，验证时长与时间轴，未评估真实语音听感。

## 4. 如何复现

文件：

- [CoreProbe.swift](repro/CoreProbe.swift)：调用公开核心接口验证拆分、合并、时间、就绪检测、输出保护及翻译结果处理。
- [AudioProbe.swift](repro/AudioProbe.swift)：生成临时信号，验证限幅、裁短与重叠轨道行为。
- [run_probes.py](repro/run_probes.py)：在临时目录编译核心库及探针，启动假翻译服务，并进行 ASGI 和错误回调验证。

使用已具备下列依赖的 Python 环境：`fastapi`、`uvicorn`、`httpx`、`python-multipart`。这些是探针导入被评审服务所需，不要求安装 mlx-audio 或准备权重。机器需具备 Xcode 和 macOS。

在仓库根目录运行：

```bash
python3 reviews/repro/run_probes.py
```

脚本将读取运行时的当前代码，在独立临时目录完成构建和测试，输出 JSON 行；所有假响应只在随机本地端口返回。执行前检查首行 baseline 是否与本报告一致；修复后的结果应改变，不能把本报告数值当作永远成立的快照。Swift 辅助代码中不同于真实基线的部分仅有 runner 明确生成的 TTS 依赖注入副本。

注意：探针故意运行可触发 fatalError 的子进程，不适合当成“所有退出码都应为 0”的生产验收套件。修复时应将每个场景转换成断言正确行为的正式回归测试。
